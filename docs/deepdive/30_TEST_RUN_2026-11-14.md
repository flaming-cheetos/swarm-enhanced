## Harness endpoints added (test-only, loopback + token + allowActions)

| endpoint | why it exists |
|---|---|
| `POST /harness/command` | run a Meteor command (`toggle swarm-safe-fire`) without a human |
| `POST /harness/chat` | send chat, or a vanilla command when it starts with `/` |
| `POST /harness/goto`, `/harness/stop-path` | drive Baritone through the path manager, not chat |
| `POST /harness/respawn` | a dead subject cannot be teleported; sends the respawn packet |
| `POST /harness/shape` | **wrong tool** — reads `getCollisionShape` directly and cannot see `CollisionShapeEvent` |
| `POST /harness/collisions` | **right tool** — counts entity collision shapes in a block, which goes through the patched sweep |

The shape/collisions pair is the lesson: Meteor fires `CollisionShapeEvent` inside
`BlockCollisions.computeNext`, so only an entity-sweep query can observe it.

## Test 1 — SafeFire: PASS

Rig: 5-wide stone corridor, walls at both sides, lava column blocking the only path.
Lava block probed at `-510 150 602`.

| module state | `collisions` result at the lava block |
|---|---|
| **on** | `count 1`, `AABB[-510,150,602] -> [-509,151,603]` — a full cube |
| **off** | `count 0`, empty |

through the corridor and stopped 3.5 blocks short. Baritone avoids lava on its own, so
the walk is corroborating evidence, not proof; the collision probe is the proof.

**Verdict:** `DONE` at the mechanism level. The Gate A exit criterion ("bot refuses to
enter a fire/lava block") is satisfied by collision override + observed refusal.

## Bugs found (fix these before Gate A)

1. **ModuleGuard restore fights manual toggles.** Turning BotBrain off calls
   `ModuleGuard.deactivate()`, which restores the *pre-guard* state — so SafeFire came
   back off exactly when a test needed it on. Symptom: "I turned it on and it turned
   itself off." For tests, enable modules **after** stopping the brain.
2. **BotBrain hunts food with nothing to hunt with.** Logs: `state=HUNTING`,
   `Food hunt: 0/20`, `hungry=true`, repeated deaths. It needs a gate: do not hunt
   hostiles at low health or with no weapon, and do not hunt in an area it cannot leave.
3. **Death screen blocks everything.** Teleports and commands are no-ops while dead.
   `/harness/respawn` was added for this; production BotBrain should also detect the
   death screen and respawn rather than sit on it.
4. **Teleporting into a structure suffocates.** Two test rigs at the base caused
   repeated 1-3 dmg/s deaths. Test rigs must be built and verified (`/execute if block`)
   before the subject is moved in, and sky platforms are safer than base interiors.
5. **Deploy script used the new commit sha before rebuilding.** The jar is stamped with
   HEAD *at build time*, so committing first and copying `...+<newsha>.jar` copies
   nothing. It deleted both jars once. Deploy must pick the newest jar by mtime.
